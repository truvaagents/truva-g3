Testing & evaluation

Testing an LLM-driven agent is fundamentally harder than testing an ordinary service. The model is non-deterministic, tools call live external systems, and "quality" is partly subjective. Every framework has to give you some answer for three things: how to write a unit test that doesn't hit a real model, how to score quality across a golden-set of test cases, and how to reproduce a bad production run locally. This chapter walks through each in plain language and compares the surfaces across the ten frameworks.

What's in this chapter

  1. Mock LLMs (and tools)
  2. Built-in eval frameworks
  3. Replay & regression testing

1Mock LLMs (and tools)

You can't run your unit-test suite against OpenAI in CI — it's expensive, flaky, and non-deterministic. So you need a fake model: something with the same interface as the real chat client but returning canned responses you control. Three of the ten frameworks ship a mock LLM in their test toolkit; the rest expect you to reach for the host language's general-purpose mocking library.

What this looks like in practice

You're testing an agent that classifies customer questions. The unit test wants to check that when the model returns "billing", the agent routes to the billing tool. With a built-in fake, the test reads: agent = make_agent(model=FakeListChatModel(responses=["billing"])) and runs offline in milliseconds. With no built-in fake, you reach for unittest.mock / Moq / Mockito and patch the chat-client interface yourself — which works but every team rebuilds the same mock-builder.

Tool mocking is a separate matter. None of the ten frameworks ships a mock-tool primitive — every team uses its host language's mock library when a tool depends on a slow or external service. The pattern is uniform enough that the absence isn't a problem in practice; it's just one more piece of test scaffolding you write yourself.

What this means in practice

Three frameworks (LangChain, LangGraph, LangChain4j) save you the small but repeat work of building a fake chat client. LangChain ships the most variants — list-cycling, message-cycling, streaming, parrot-style echo — covering most of the test scenarios you'll write. The other seven expect you to reach for the host language's mocking library (unittest.mock, Moq, sinon, vitest, Mockito, custom Go callbacks, custom Rust trait impls). Either approach works; only the convenience differs.

2Built-in eval frameworks

You changed a prompt. Did the agent get better or worse on the dozen scenarios that matter? An eval framework gives you a way to express "run the agent on these test cases and score each one" without rebuilding the runner, the metric, and the comparison view yourself. Six of the ten frameworks ship a meaningful eval framework — five mature, plus CrewAI's experimental module. The others leave you to wire something like Promptfoo, DeepEval, or your own scaffolding.

What this looks like in practice

You're about to ship a prompt change. Before merging the PR, you want to know: did this change improve quality on the 50 test scenarios you've curated, or regress? With a built-in eval framework, you have a list of EvalCase objects (input, expected output, expected tool calls), pick scorers (correctness, faithfulness, tool-call accuracy), run the suite, and get a pass/fail report comparing this run to the baseline. Without one, you build the runner, the scoring logic (often calling another LLM as a judge), and the comparison report from scratch — which most teams do in a Jupyter notebook that becomes load-bearing infrastructure.

Two important sub-features: LLM-as-judge (using a model to score whether an answer is good) and golden-set replay (re-running a curated set of test cases against the agent). Most production-grade eval frameworks bundle both.

What this means in practice

Five frameworks ship mature eval frameworks: LangChain, ADK, Mastra, MS Agent Framework, and Genkit Go. The breadth varies — LangChain has the largest scorer catalogue and the longest-running ecosystem; ADK has the most production-grade artifacts (named EvalCase / EvalSet types, scenario generator, simulation submodule); Mastra has the broadest scorer count (twelve including toxicity, bias, hallucination, trajectory); MS Agent Framework integrates with Microsoft.Extensions.AI.Evaluation; Genkit Go is the smallest but covers the basics. CrewAI ships a sixth eval framework under experimental/evaluation/ — comparable in shape (multiple metric evaluators, an experiment runner) but flagged experimental.

The other four (LangGraph leans on LangChain's; SK Python / LangChain4j / Rig ship nothing) expect you to wire an external eval tool — Promptfoo, DeepEval, Ragas, or a Jupyter notebook with custom scoring. That works, but you lose the framework's awareness of how to run agents reproducibly under test conditions.

3Replay & regression testing

A user reports a bad answer in production. You want to reproduce it locally — same prompts, same tool responses, same model state — so you can put a debugger inside the agent and figure out what went wrong. That's replay: re-executing a recorded run offline. Two of the ten frameworks ship something close to it; the others ask you to reconstruct from logs.

What this looks like in practice

At 9 AM, a customer escalates: the bot recommended an expired promo code. With replay, you pull the trace for that conversation, load the stored state into your local agent, and step through what happened — same model responses, same tool outputs, same intermediate state. You can see that the model misread a context field on step 3 and confidently propagated the wrong value to step 4. Without replay, you eyeball the trace, hand-craft a Python script that matches the prompt, and hope you reproduce the failure.

Replay also matters for regression. Before merging a prompt change, you want to re-run it against the same scenarios that have failed before — not just synthetic evals, but real captured production runs. The frameworks that ship replay are the ones that make this realistic.

What this means in practice

First-class replay belongs to two frameworks: LangGraph (via the checkpointer model — every super-step is recorded and any snapshot is replayable) and ADK (via the eval framework's EvalCase abstraction, which defines a replayable scenario as the unit of testing). LangChain inherits LangGraph's path through LangSmith. The other six frameworks have no first-class replay — production debugging falls back to reading traces and reconstructing what happened by hand.

On snapshot testing: only LangChain and LangGraph use snapshot testing in their own test suites (via the syrupy library; LangGraph stores .ambr files at tests/__snapshots__/). It's used for framework-internal schema validation, not for agent-output regression — but it's the only place where snapshot testing as a pattern is visible across the catalog.

At a glance

Source-grounded observations on testing surfaces across the ten frameworks.

MOCK LLMS

1 · Three frameworks ship a mock LLM

LangChain (five fake-model variants in fake_chat_models.py), LangGraph (extends LangChain's via tests/fake_chat.py), and LangChain4j (ChatModelMock + StreamingChatModelMock, marked @Experimental). The other seven expect you to reach for the host language's mocking library.

MOCK TOOLS

2 · Tool mocking is universally absent

None of the ten frameworks ships a mock-tool primitive. Every team uses unittest.mock / Moq / Mockito / sinon and stubs the tool function directly. Uniformly absent across the catalog — and uniformly easy to work around.

EVALS

3 · Six frameworks ship eval frameworks (five mature)

LangChain (longest-running scorer catalog), ADK (largest production-grade module with EvalCase/EvalSet, scenario generator, simulation), Mastra (twelve scorers including toxicity, bias, hallucination, trajectory), MS Agent Framework (integrated with Microsoft.Extensions.AI.Evaluation), Genkit Go (plugin-based). CrewAI's experimental module adds a sixth at experimental/evaluation/.

JUDGE

4 · LLM-as-judge ships in every eval framework that ships

All six frameworks with eval support include an LLM-as-judge implementation — using a separate model call to score whether an answer is correct, faithful, or satisfies a rubric. The pattern has converged: it's now what production-grade eval frameworks look like.

REPLAY

5 · First-class replay only in LangGraph and ADK

LangGraph's checkpointer model writes every super-step and lets get_state() rehydrate any snapshot. ADK's EvalCase abstraction defines replayable scenarios as the unit of testing. Everywhere else, reproducing a production run means reading traces and hand-crafting the inputs.

SNAPSHOT

6 · Snapshot testing is a LangChain-family habit

LangChain and LangGraph use the syrupy library for snapshot tests in their own test suites; LangGraph stores .ambr files at tests/__snapshots__/. The pattern is for framework-internal schema validation rather than agent-output regression — but it's the only place where snapshot testing shows up as a discipline across the catalog.
